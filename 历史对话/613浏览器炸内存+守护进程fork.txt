**根因找到了：`app.run(debug=True)`。**

Flask 的 debug 模式自带 `use_reloader`，reloader 检测到代码变化（或者甚至 Python 自身文件改动）就会 fork 新进程。问题是：
1. deamon 每分钟检查一次，发现 `step6_web` 还活着就没事
2. 但 reloader 自行 spawn 了新进程，旧进程不一定在真正退出
3. 5:50 浏览器崩溃后，`main_loop.py` 在不停地报错重启，而 `step6_web` 的 debug reloader 也在每次冲突时 fork 新进程
4. 从凌晨跑到现在，119 个 Flask 实例叠起来了

要处理的话我可以帮你：**一次性杀掉所有 `step6_web` 进程 + 禁用 debug 模式**，让 daemon 重启时只起一个干净的实例。需要动手吗？
